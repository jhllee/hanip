# hanip — 에디토리얼 디자인 실험

2026-10-15. 브랜치 `codex/hanip-editorial`, 기존 구현 기준점 `8b6a904`.

## 디자인 기준

개인 디지털 매거진과 시각적인 지식 서재를 지향합니다. 배경 #F8F6F1, 본문 #24231F, 작은 살구색 강조 #E9AC8E를 사용합니다. 본문은 한국어 시스템 sans-serif, 영문 로고는 시스템 Georgia입니다. 외부 폰트·새 패키지·랜덤 이미지를 추가하지 않았습니다.

[Kinfolk](https://www.kinfolk.com/)와 [Cosmos](https://www.cosmos.so/)의 홈페이지를 웹과 실제 브라우저 화면으로 확인했습니다. 큰 타이포그래피·여백과 이미지 그리드·절제된 조작을 참고했으며 사이트 자산이나 레이아웃을 복제하지 않았습니다.

상단에 소문자 hanip 로고·서비스명·실제 메뉴·데이터 관리를 배치합니다. 오늘 화면은 작은 날짜와 핵심 문구, 좌우 추천 영역과 가장 큰 기사 제목, 편집자 노트, 먹색 읽어보기 버튼으로 구성합니다. 모바일에서는 세로로 배치합니다. 현재 제품의 주제 선택을 작게 유지하며 제거하기로 한 가볍게/깊이 있게 UI는 되살리지 않았습니다.

보관함의 새 기본 보기는 카드형입니다. 기존 브라우저의 카드/목록 선택이 있으면 그대로 복원합니다. 카드 외곽 박스와 그림자를 없애고 이미지 → 제목 → 도메인을 우선합니다. 이미지가 없으면 도메인 해시로 정한 크림·살구·회녹 계열 표지에 제목과 작은 도메인을 표시합니다. 기존 이미지 실패 전환과 lazy loading을 유지합니다.

검색·주제 필터·보기 전환·정렬·URL/TXT 저장·완독·즐겨찾기·삭제·실행 취소·JSON 메뉴는 실제 동작에 연결합니다. 빈 상태·로딩·오류·완독·모달·토스트를 같은 색과 타이포그래피로 맞췄습니다. 그라데이션·장식용 AI 아이콘과 가짜 지표를 추가하지 않았습니다.

## 기능·데이터 보존

`src/store`, `src/lib`, `src/types`, `src/app/api`, package 파일은 기준 커밋과 동일합니다. localStorage 키·버전2·마이그레이션·Bookmark/DailyRecommendation/JSON 형식을 변경하지 않았습니다. 사용자 서재 대신 별도 localhost:3006의 공개 테스트 URL과 샘플만 사용했습니다. 원본 작업 폴더55개 파일을 기준 커밋과 대조해 차이 없음을 확인했습니다.

- 1280px에서 좌우 추천과 3열 그리드, 390px에서 1열 배치, 320px에서 가로 넘침 없음을 확인. 키보드 Tab 이동의 포커스 링 확인. prefers-reduced-motion 스타일 유지.

- 실제 Gemini 호출 성공은 이번 UI 작업에서 재검증하지 않았습니다. 서버 코드를 유지하고 모의 성공/실패·키 미설정 fallback은 자동 테스트로 검증했습니다. 미리보기는 키 없는 기본 추천을 사용합니다.

## 로고를 유지한 본문 밀도 조정

큰 hanip 로고(데스크톱58px·모바일44px)와 헤더 스타일은 그대로 유지합니다. 페이지 제목 주변 여백을 적당히 줄이고 오늘 화면에서는 설명을 제목 옆에 배치합니다. 추천 이미지·제목·편집자 노트 간격을 줄이고, 오늘 화면의 중복 브랜드 푸터를 숨깁니다. 모바일 추천 커버는 짧은 가로 표지로 표시합니다. 내용이 길면 자연스럽게 늘어나며 본문이나 조작 버튼을 잘라서 스크롤을 숨기지 않습니다.

기존 RFC 추천으로1280×720 및390×844에서 문서 높이가 화면 높이와 같고 읽기 버튼까지 표시됨을 확인했습니다. 320px 읽을거리·보관함의 가로 넘침 없음도 확인했습니다. 긴 제목·설명, 작은 화면, 확대 설정에서는 스크롤이 필요할 수 있습니다. 프로덕션 빌드(타입 검사 포함)와 린트가 통과했습니다. 기능과 저장 데이터 형식은 변경하지 않았습니다.

## 화면 제목 통일

오늘 탭의 큰 제목을 오늘한입으로 바꾸고, 모아둔 글, 오늘은 한입. 문구를 작은 설명으로 배치했습니다. 모든 탭은 동일한 제목 크기(데스크톱28px·모바일25px), 제목 상단 위치, 설명 배치, 하단8px 간격을 사용합니다. 로고는 유지합니다. 데스크톱 네 탭의 제목 스타일과 상단 위치147px가 동일함을 확인했습니다. 기존 RFC 추천으로1280×720·390×844에서 오늘 화면에 스크롤이 없음을 다시 확인했습니다. 빌드(타입 검사 포함)·린트 통과.

## 제목 영역 간소화

화면 제목은 오늘 한입으로 띄어 쓰고, 제목 위의 오늘의 한입·영문 라벨과 장식 점을 삭제했습니다. 모든 탭은 제목과 작은 설명으로 통일하고 오늘의 날짜만 오른쪽에 배치합니다. 서비스 이름·메타데이터는 오늘한입을 유지합니다. 320px에서 네 탭 가로 넘침 없음,1280×720·390×844에서 기존 RFC 추천 전체 표시 및 스크롤 없음 확인. 빌드(타입 검사 포함)·린트 통과.

## 매거진의 여유 복원

상단 추천 안내와 주제 선택을 데스크톱에서 한 줄로 묶고 중복 주제 라벨을 제거했습니다. 확보한 공간을 큰 기사 제목과380px 높이 추천 이미지(1280×720 기준)에 배분하고 제목·설명·노트·버튼 사이 간격을 넓혔습니다. 모바일에서는 도구를 자연스럽게 세로로 배치합니다. 테스트한 RFC 추천에서1280×720·390×844 전체 표시, 스크롤 없음과 모바일 가로 넘침 없음을 확인했습니다. 빌드(타입 검사 포함)·린트 통과.

## 목록 시작선과 헤더 저장 동작

링크 추가를 공통 헤더로 옮겼으며 어느 탭에서든 읽을거리 URL 입력창을 열고 포커스를 이동합니다. 검색을 각 목록 제목 오른쪽으로 옮기고 주제·보기 방식·정렬은 한 줄로 모았습니다. 보관함의 첫 날짜를 도구 줄에 배치하고 날짜별 그룹 구조·이후 날짜 표시는 유지했습니다. 모바일에서는 검색과 도구를 줄바꿈하며 데이터 관리 아이콘에 접근성 이름을 지정했습니다.

추천 이미지 높이를 더 줄였습니다. 기존 RFC 추천의1280×680 화면에서 이미지 높이302px·스크롤 없음, 오늘·읽을거리·보관함의 이미지 시작 높이325.6px가 동일함을 확인했습니다. 390×844 오늘 화면 스크롤 없음,320px 읽을거리·보관함 가로 넘침 없음 확인. 오른쪽 도메인 검색으로1개 결과와 초기화4개 복원, 오늘에서 헤더 링크 추가 → 읽을거리 입력창 표시·포커스 확인. 빌드(타입 검사 포함)·린트 통과.

## 목록 카드 이미지 축소

목록 커버를16:9 가로형으로 변경하고 화면 높이에 맞춘 최대 높이(120~210px)를 적용했습니다. 텍스트 커버의 장식 영문은 제거하고 제목 두 줄·도메인을 유지합니다. 오늘 추천 커버는 변경하지 않았습니다.1280×680 테스트에서 목록 이미지130px, 읽을거리 첫 줄 최대 하단679px(메타데이터 오류 안내 포함), 보관함657px, 즐겨찾기650px로 첫 줄 조작 버튼까지 표시됨을 확인했습니다. 390px 모바일 즐겨찾기 첫 카드 하단768px·가로 넘침 없음 확인. 긴 콘텐츠·더 낮은 화면에서는 추가 스크롤이 필요할 수 있습니다. 빌드(타입 검사 포함)·린트 통과.
