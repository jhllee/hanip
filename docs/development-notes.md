# 개발 기록

> README에서 분리한 구현·검증 기록입니다. 각 기록의 상태와 제한은 작성 당시 기준이며, 현재 사용법은 [프로젝트 README](../README.md)를 참고하세요. 기록에 언급된 로컬 스크린샷은 저장소에 포함하지 않습니다.

**모아둔 글, 오늘은 한입.**

정보를 모으지만 읽기는 미루는 사람을 위한 개인 지식 서재입니다. AI 큐레이터 **한입이**가 저장한 글 중 오늘 읽을 한 편을 고릅니다.

## 현재 상태 — Step 4 구현 완료

URL 저장 → 오늘의 한 편 추천 → 새 탭에서 원문 읽기 → 완독 → 보관함 이동을 연결했습니다. 최초 서재는 비어 있으며, 샘플은 직접 선택할 때만 추가됩니다.

- 오늘 / 읽을거리 / 보관함 / 즐겨찾기, 한국어 UI와 반응형 카드
- URL 즉시 저장, TXT 링크 모음 미리보기·중복 제거, 메타데이터 실패·재시도
- 제목·설명·도메인 검색과 최신/오래된 저장순 정렬
- 날짜·읽기 방향·주제별 당일 추천 캐시, Gemini 실패 시 기본 추천
- 기본 추천 즉시 표시, 백그라운드 AI 결과는 ‘AI 추천 보기’를 눌렀을 때 적용
- 원래 설명이 없는 항목의 제목 기반 AI 안내. 본문 요약이나 독서 시간은 생성하지 않음
- 완독과 삭제 실행 취소, JSON 백업·병합 가져오기, 중복 없는 샘플 7개
- 브라우저 저장 검증·마이그레이션·hydration·저장 실패 안내

프로덕션 빌드가 통과한 로컬 MVP입니다. 실제 호스팅 배포는 아직 수행하지 않았습니다. 파일 가져오기는 로직 검증을 완료했지만 브라우저 파일 선택부터 병합까지의 통합 확인은 아래 기록처럼 남아 있습니다.

## 실행과 검증

Node.js **22.12 이상**을 사용합니다. 검증 환경은 Node.js 24입니다.

```sh
npm ci
cp .env.example .env.local
npm run dev
```

[개발 화면](http://localhost:3000)을 엽니다. Gemini를 사용하지 않으면 환경 파일 없이도 저장·검색·기본 추천·완독을 사용할 수 있습니다.

개발 서버는 요청 헤더를 최대 64 KiB까지 허용합니다. 다른 로컬 프로젝트와 공유하는 localhost 쿠키 때문에 Safari 일반 창에서 `431 Request Header Fields Too Large`가 발생하는 경우를 위한 개발 전용 설정입니다. 이 설정을 변경한 뒤에는 개발 서버를 다시 시작합니다. 브라우저 웹사이트 데이터를 삭제하면 저장된 서재도 지워질 수 있으므로 삭제할 필요가 없습니다.

```sh
npm test
npm run lint
npm run typecheck
npm run build
npm start
```

`npm start`는 프로덕션 빌드 후 실행합니다. 각 검증은 `test:store`, `test:links`, `test:recommendation`, `test:reading-ai`, `test:backup`으로 따로 실행할 수 있습니다.

## 환경변수와 AI

| 이름 | 설정 |
| --- | --- |
| `GEMINI_API_KEY` | 서버에서만 사용하는 Gemini API 키. 미설정 시 기본 추천 |
| `GEMINI_MODEL` | 현재 환경 예시 `gemini-3.1-flash-lite` |

`.env.local`은 버전 관리에서 제외합니다. 키 이름에 `NEXT_PUBLIC_` 접두사를 붙이지 않습니다. 키는 클라이언트 번들·localStorage·JSON 백업에 포함하지 않습니다. 서버 환경변수를 변경하면 실행 서버를 다시 시작합니다.

`@google/genai`의 `GoogleGenAI.models.generateContent`, `responseMimeType`과 `responseJsonSchema`로 구조화 출력을 받습니다. [Google SDK](https://googleapis.github.io/js-genai/release_docs/index.html), [지원 모델](https://ai.google.dev/gemini-api/docs/models), [구조화 출력](https://ai.google.dev/gemini-api/docs/generate-content/structured-output)은 2026-10-13 구현 시 확인했습니다. 실제 키의 모델 권한과 가용성은 배포 환경마다 확인해야 합니다. 모델 변경과 실제 성공·실패 기록은 아래 구현 이력에 있습니다.

한입이는 제목·원래 설명·저장 경과일·즐겨찾기만 사용합니다. 원문 본문은 전송하지 않습니다. 최대 30개의 미완독 후보로 제한하고 서버가 저장 경과일을 계산합니다. 북마크 텍스트 안의 지시는 신뢰하지 않으며 후보 id·출력 스키마·실제 인용 구절을 검증합니다. 의미적 사실 검증을 완전히 보장하지는 않으므로 본문을 확인한 것처럼 말하지 않도록 지시하고 UI에도 한계를 표시합니다.

AI 호출 실패·키 미설정·잘못된 응답·12초 타임아웃에는 오래된 미완독 글을 기본 추천합니다. 클라이언트 제한은 15초입니다. 미완독 글이 없으면 AI를 호출하지 않습니다. 오늘의 글을 읽으면 완료 상태를 유지하며 다음 글로 자동 전환하지 않습니다.

## 데이터와 백업

데이터는 이 브라우저에 저장돼요. 기기 간 동기화는 지원하지 않아요. 주소·브라우저가 달라지면 별도의 서재가 됩니다.

Zustand persist 키는 `oneul-hanip-library`, 저장 버전은 **2**입니다. v0/v1 데이터를 검증해 aiGuide/topic 기본값을 보충합니다. 손상 데이터나 미지원 버전은 원본을 보존하고 해당 세션의 저장을 차단합니다. 저장 공간 오류 시 메모리 변경과 경고를 유지하므로 탭을 닫기 전에 백업이 필요합니다.

**데이터 관리**에서 JSON을 내보내거나 가져옵니다. 백업은 `schemaVersion: 1`, `exportedAt`, `bookmarks`로 구성하며 완독·즐겨찾기·AI 안내를 포함합니다. 당일 추천과 API 키는 내보내지 않습니다.

- JSON 파일은 UTF-8, 최대 **5 MiB**. 서재는 최대 **10,000개**입니다. 내보내기도 다시 가져올 수 있도록 5 MiB를 넘으면 오류를 안내합니다.
- 파일 구조·필드·URL·읽음 일시를 전체 검증하며 한 항목이라도 잘못되면 기존 서재를 변경하지 않습니다.
- `normalizedUrl`을 신뢰하지 않고 원본 URL에서 재계산합니다. fragment·알려진 추적 파라미터는 제거하고 콘텐츠 쿼리는 보존합니다.
- 미리보기 후 ‘서재에 병합하기’로 추가합니다. 기존 글은 덮어쓰지 않으며 URL 중복은 건너뛰고 다른 URL의 id 충돌은 새 id를 만듭니다.
- 가져온 pending 메타데이터는 failed로 바꿔 다시 시도할 수 있게 합니다. 성공 후 가져온 개수와 중복 개수를 표시합니다.
- ‘샘플로 둘러보기’는 정상 이미지·텍스트 커버·정보 가져오기 실패 사례를 포함한 7개를 추가하며 반복 선택으로 중복 생성하지 않습니다.
- 실행 취소는 최근 최대 3개 알림에서 가능합니다. 알림 닫기·새로고침 이후에는 복구하지 않으며 이후 변경을 덮어쓰지 않습니다.

## 배포 안내와 한계

Node.js 서버 실행을 지원하는 Next.js 호스팅에 프로젝트를 배포합니다. 메타데이터 API가 Node DNS/IP 검증을 사용하므로 **Node 런타임**과 서버 API가 필요합니다. 정적 파일 전용 호스팅이나 static export는 사용할 수 없습니다.

1. Node.js 22.12 이상을 선택하고 설치 `npm ci`, 빌드 `npm run build`, 시작 `npm start`를 설정합니다. 호스팅의 Next.js 자동 실행 환경에서는 별도 시작 명령이 필요 없을 수 있습니다.
2. AI를 사용하려면 호스팅의 서버 환경변수에 `GEMINI_API_KEY`, `GEMINI_MODEL`을 설정합니다. `.env.local`을 공개 저장소에 올리지 않습니다.
3. 서버의 외부 DNS·HTTPS 요청을 허용하고 함수 실행 시간은 AI의 12초 제한보다 길게 설정합니다. 메타데이터 수집은 검증된 공개 IP로만 연결합니다.
4. 배포 주소에서 URL 저장·추천·원문·완독·새로고침·백업을 확인합니다. localhost 데이터는 배포 주소로 자동 이동하지 않으므로 JSON 백업을 옮깁니다.

Gemini API에는 인스턴스 전체 동시 **2회**, 분당 **10회**, 24시간당 **100회**의 메모리 상한을 적용하며 추천과 제목 안내가 공유합니다. 재시작 시 초기화되고 다중 인스턴스 간 공유되지 않으며 사용자별 인증 제한이 아닙니다. 공개 서비스 운영에는 호스팅의 전역 요청·비용 상한 등 추가 보호가 필요합니다. 제목 안내를 생성할 때 해당 제목이 Google로 전송됩니다. 메타데이터 저장 시 대상 사이트로 요청하고 이미지·favicon은 브라우저에서 로드합니다.

메타데이터 요청은 DNS 해석 결과와 모든 리다이렉트 목적지의 공개 IP를 확인하고 연결 IP를 고정합니다. localhost·사설·링크 로컬·특수 주소를 차단하고 10초·리다이렉트 5회·HTML 2 MiB 제한을 적용합니다. 로그인·동적 페이지·대상 사이트 정책 때문에 정보를 얻지 못해도 URL은 유지합니다. 이미지는 실패 시 도메인별 텍스트 커버로 전환합니다. Microlink는 연결하지 않았습니다.

로그인·외부 DB·결제·브라우저 확장·본문 리더·자동 태그·기기 동기화는 이번 범위에 포함하지 않습니다.

## Step 4 확인 기록 — 2026-10-14

- 자동 테스트 **54개** 통과: 저장소9, 링크/메타데이터13, 추천17, 읽기 선택/AI 안내6, 백업/실행 취소9.
- ESLint·타입 검사·프로덕션 빌드 통과. `npm audit --omit=dev`의 런타임 의존성 취약점 0건. 개발 의존성의 기존 braces 감사 항목은 아래 Step 0 기록 참조.
- 백업 검증: 잘못된 JSON·버전·필드·URL·읽음 일시·크기 거절, URL 재정규화·파일 내외 중복·id 충돌·콘텐츠 쿼리·pending 복구·백업 왕복.
- 실행 취소 검증: 완독 일시 복원, 삭제 복원, 이후 즐겨찾기 변경 보존, 이후 삭제·중복 URL과 충돌 시 덮어쓰기 방지.
- Gemini 키를 비운 별도 프로덕션 테스트 주소 `localhost:3002`에서 빈 최초 서재, 샘플7개·반복 추가0개/중복7개, 원문 클릭 시 미완독 유지, 완독·보관함 이동, 완독/삭제 실행 취소, 새로고침 후 북마크와 추천 유지 확인.
- 390px 모바일에서 1열 카드·검색·정렬·완독·데이터 관리 배치를 확인. 모든 글을 읽은 후 완료 추천 유지와 다른 방향에서 ‘모아둔 글을 모두 읽었어요.’ 표시 확인.
- 실제 내보내기 파일의 최상위 필드3개와 북마크7개를 확인. 설정된 키 값이 프로덕션 클라이언트 정적 파일12개 및 내보내기 JSON에 없음을 출력 없이 대조했습니다.
- **브라우저 파일 가져오기 통합 확인은 미실행:** 테스트 JSON을 선택하는 단계가 브라우저 보안 검토의 권한 거절로 중단됐습니다. 우회하지 않았으며 해당 기능의 구조·실패·병합은 위 자동 테스트로 검증했습니다. 실제 파일 선택 → 미리보기 → 병합 → 새로고침은 수동 확인이 남아 있습니다.
- 기존 `localhost:3000` 사용자 서재에는 테스트 글을 추가하거나 변경하지 않았습니다. 실제 공개 배포는 하지 않았습니다.

## 이전 단계 구현 이력

아래는 각 단계 완료 당시의 기록입니다. ‘아직’, ‘예정’ 등의 표현은 해당 시점 기준이며 현재 상태와 제한은 위 내용을 따릅니다.

## Step 0 확인 기록

- 타입 검사 및 프로덕션 빌드 성공. 빌드는 작업 환경의 내부 포트 제한 때문에 권한 승인 후 실행했습니다.
- ESLint 경고·오류 없이 통과. 임시 검증 스크립트로 정상 URL, 잘못된 URL·프로토콜·인증 정보, 잘못된 AI 출력, 백업 버전을 포함한 기초 스키마 검증 9건을 실행해 통과했습니다. 전체 가져오기·추천 기능 검증은 해당 기능 구현 후 추가합니다.
- 본문·보조 문구·강조색과 배경/카드 간 대비를 계산해 모두 4.5:1 이상 확인했습니다(최소 4.82:1). 브라우저에서의 시각적 검수는 아직 수행하지 않았습니다.
- Gemini API 호출, 메타데이터 요청, 브라우저에서의 핵심 사용자 흐름은 아직 검증하지 않았습니다.
- 의존성 감사에서 개발용 `eslint-config-next`의 `braces` 하위 의존성에 관련된 높은 심각도 항목 5개가 보고됐습니다. 설치 시점의 최신 `braces`도 3.0.3으로 수정 버전이 없어 기록합니다. 런타임 요청 처리에 사용하는 의존성은 아니며, Next.js와 맞지 않는 구버전 lint 설정으로 강제 하향하지 않았습니다. 수정 버전 출시 시 업데이트가 필요합니다.

## Step 1 — 저장소와 서재 화면

오늘을 기본으로 읽을거리·보관함·즐겨찾기 화면을 구성했습니다. 데스크톱은 220px 왼쪽 메뉴, 모바일은 상단 메뉴를 사용합니다. URL 입력과 검색 입력은 분리했습니다. 카드에는 도메인별 텍스트 커버, 이미지 실패 fallback, 원문 링크, 완독·즐겨찾기 버튼이 있습니다. 카드 전체 링크 안에 버튼을 중첩하지 않았습니다.

- `src/store/library.ts`: Zustand persist v1, 명시적 hydration, 북마크 및 날짜·모드별 추천 저장, 중복 거절, 추천 참조 재검증
- `src/lib/library-data.ts`: 저장 데이터 검증, v0→v1 변환, 로컬 날짜 및 저장 경과일 도우미
- `src/components/library-app.tsx`: 오늘·목록 화면, 완료 상태, 검색·정렬 UI와 데이터 관리 안내
- `src/components/bookmark-cover.tsx`: 도메인 해시별 5가지 커버, 이미지 실패 시 텍스트 전환

저장소를 읽기 전에는 로딩 상태를 표시합니다. 손상 데이터와 미지원 버전은 원본을 보존하고 해당 세션의 저장을 차단합니다. 저장 공간 초과 등 쓰기 오류가 발생하면 변경 사항을 메모리에서 유지하면서 경고를 표시하며, 이후 정상 저장이 되면 경고를 해제합니다. v0 변환은 현재 Bookmark 형식에 추천 배열만 없는 구조를 지원합니다. 임의의 과거 앱 형식은 추측해서 변환하지 않습니다.

완독된 오늘의 추천은 완료 상태로 유지하고 자동으로 다른 글을 고르지 않습니다. 삭제된 항목에 대한 추천 참조는 제거합니다. 추천 저장 함수는 실제로 존재하는 미완독 항목만 허용합니다.

```sh
npm run dev
npm run test:store
npm run lint
npm run typecheck
npm run build
```

자동 테스트 7건에서 빈 초기 상태, 중복 거절 및 새 저장소 인스턴스의 복원, 추천 유지, 완독 취소 시 readAt 초기화, 삭제 참조 제거, 손상/미지원 데이터 보존, v0 변환, 저장 공간 오류를 확인했습니다. 사용자 브라우저에 테스트 글을 주입하지 않았으며 최초 서재는 비어 있습니다.

Step 1 완료 시점에는 URL 저장을 비활성화했으며 Step 2에서 연결했습니다.  자동 추천·다른 글 추천은 Step 3, 삭제·실행 취소 토스트·JSON 백업·샘플은 Step 4에서 연결합니다. 검색·정렬 및 완독·즐겨찾기 기본 상태 변경은 화면을 확인할 수 있도록 연결했지만 전체 핵심 흐름의 브라우저 검증은 해당 기능 연결 후 수행합니다.

## Step 2 — URL 저장과 TXT 링크 모음

개별 URL은 유효성·중복 검사를 거쳐 도메인을 임시 제목으로 즉시 저장합니다. 글 정보는 브라우저 전체에서 한 번에 하나씩 요청합니다. 실패해도 저장 항목과 원문 링크는 유지되며 카드에서 **다시 시도**할 수 있습니다. 새로고침으로 중단된 pending 항목은 다음 방문에 이어서 가져옵니다. 동일 id의 중복 요청을 막고, 삭제되거나 URL이 바뀐 항목에 늦은 응답을 반영하지 않습니다.

**TXT로 한 번에 담기**에서 UTF-8 `.txt` 파일을 선택하세요. 파일은 브라우저에서 읽으며, 전체 파일을 서버에 업로드하지 않습니다. 저장을 누른 후 각 URL만 메타데이터 API로 전송합니다.

```text
https://example.com/article-one
example.org/article-two
https://example.net/article?id=3
```

- 한 줄에 URL 하나, 빈 줄은 무시, 최대 100개의 비어 있지 않은 줄, 256 KiB 이하
- BOM·CRLF·LF 지원, 잘못된 UTF-8 및 바이너리 거절
- 저장 전 새 링크·기존/파일 내부 중복·잘못된 줄 개수와 일부 URL 미리보기
- 잘못된 줄 번호 확인 가능, 중복/잘못된 줄은 건너뛰고 유효한 새 URL만 병합
- 미리보기 후 저장 시 최신 서재 기준으로 중복 재검사, 파일 전체 구조 오류 시 기존 데이터 보존
- 기존 데이터 포함 최대 10,000개, 중복만 있으면 저장 버튼 비활성화

정규화는 프로토콜이 생략된 도메인에 https를 붙이고 fragment 및 `utm_*`, `fbclid`, `gclid`, `dclid`, `msclkid`, `mc_cid`, `mc_eid`, `igshid`, `_ga`, `_gl`을 중복 기준에서 제거합니다. 실제 원문 URL의 fragment는 유지합니다. 콘텐츠 쿼리와 쿼리 순서를 보존하며 http/https 외 스킴과 인증 정보를 포함한 URL은 거절합니다.

### 메타데이터 API와 SSRF 방어

`POST /api/metadata`는 Node.js 런타임을 사용합니다.

- 요청 본문 최대 8 KiB, 읽기 제한 3초, Zod 입력 검증
- 외부 요청은 DNS·리다이렉트·응답 수신을 합쳐 최대 10초, 최대 5회 리다이렉트
- DNS의 모든 결과를 `ipaddr.js`로 분류하며 하나라도 비공개/특수 주소이면 거절
- IPv4·IPv6·IPv4-mapped, 사설/루프백/링크 로컬/예약 대역 및 내부 도메인 차단
- 검증된 IP를 Node HTTP `lookup`에 고정해 연결 중 DNS 재해석 방지, 원래 Host/TLS 인증서 검사 유지, 연결 풀 재사용 안 함
- HTML/XHTML만 허용, 응답 헤더 최대 16 KiB, 응답 본문 최대 2 MiB(헤더와 수신 스트림 모두 검사)
- 일반 웹 포트 80/443만 허용. `Accept-Encoding: identity`를 사용하며 압축을 강제하는 사이트는 이번 단계에서 가져오기 실패로 처리
- Cheerio로 HTTP charset·HTML charset을 고려해 파싱(선언이 없으면 UTF-8), OG→기본 태그 순서 적용, 이미지·favicon 상대 경로는 최종 URL 기준으로 변환
- 외부 텍스트는 React 텍스트로 표시하고 HTML로 주입하지 않음

[Node HTTP 요청 문서](https://nodejs.org/api/http.html), [DNS lookup 문서](https://nodejs.org/api/dns.html), [Cheerio 버퍼 로딩 문서](https://cheerio.js.org/docs/basics/loading/)를 참고했습니다. DNS/IP 검사는 형식 검증과 별개입니다. 페이지가 로그인·동적 렌더링·봇 차단을 요구하거나 서버 네트워크에서 연결할 수 없으면 글 정보를 가져오지 못할 수 있습니다.

서버 메모리 기준 동시 8개, 인스턴스 전체 분당 240개로 제한합니다. 이는 사용자별 제한이 아니므로 다른 사용자의 요청도 한도를 공유합니다. 재시작 때 초기화되고 다중 인스턴스 간 공유되지 않습니다. 실제 공개 배포에서 더 강한 제한이 필요하면 호스팅의 게이트웨이 제한 등을 추가해야 합니다. 비용이 발생하는 Gemini 추천 API 제한은 Step 3에서 별도로 구현합니다.

## Step 3 — 오늘의 한 편 추천

오늘 화면에 들어가면 해당 로컬 날짜·모드의 추천을 먼저 복원합니다. 없는 경우에만 미완독 글로 추천 API를 호출합니다. 모드를 다시 선택하거나 새로고침해도 당일 캐시를 재사용합니다. **다른 글 추천**은 다른 미완독 글이 있을 때 현재 글을 제외합니다. 완독 직후에는 완료 상태를 유지하고 자동으로 새 글을 고르지 않습니다.

서버 후보는 오래된 미완독 글 20개를 먼저 확보하고 오래된 즐겨찾기를 포함해 최대 30개로 제한합니다. 즐겨찾기가 없거나 겹치면 나머지를 오래된 글로 채웁니다. 서버가 저장 경과일을 계산하고, Gemini에는 id·제목·설명·저장 경과일·즐겨찾기 여부만 전달합니다. 토큰 사용을 제한하기 위해 제목은 앞 300자, 설명은 앞 1,000자까지만 전달합니다. URL·이미지·본문·API 키는 전달 데이터에 포함하지 않습니다.

- 균형: 저장 경과일과 즐겨찾기 관심 신호 고려
- 가볍게: 제목·설명의 입문, 기초, 짧은 팁 등의 단서 고려
- 깊이 있게: 분석, 가이드, 해설 등의 단서 고려
- 기본 추천: 모드와 관계없이 오래된 미완독 글부터 선택하며 UI에 **기본 추천** 표시

### Gemini 연결과 사실 기반 이유

2026-10-13 [공식 모델 목록](https://ai.google.dev/gemini-api/docs/models)에서 `gemini-3.5-flash-lite` 안정 버전을 다시 확인했습니다. [SDK GenerateContentConfig](https://googleapis.github.io/js-genai/release_docs/interfaces/types.GenerateContentConfig.html)와 설치된 `@google/genai@2.29.0` 타입을 확인하고 `GoogleGenAI.models.generateContent`를 연결했습니다.

응답 스키마에서 실제 후보 id와 사실 기반 이유 문장을 enum으로 제한합니다. 이유는 저장 경과일·즐겨찾기·실제로 포함된 제목/설명 단서에서 만든 한국어 1~2문장입니다. 서버가 반환 스키마, 후보 id, 선택 항목과 이유의 일치까지 검증합니다. 이 방식은 AI가 자유롭게 이유를 작성할 때 생기는 추측을 제한하기 위한 의도적인 선택입니다. 단서가 부족하면 본문을 확인하지 않았고 깊이·독서 시간을 알기 어렵다고 안내합니다.

제목·설명은 신뢰할 수 없는 데이터로 취급하고 안의 지시를 따르지 않도록 시스템 지시와 JSON 데이터로 분리했습니다. 외부 본문은 수집하지 않으며 정확한 독서 시간이나 확인하지 않은 난이도를 표시하지 않습니다.

환경변수는 `.env.local` 또는 호스팅의 서버 설정에만 넣고 개발 서버를 재시작합니다.

```text
GEMINI_API_KEY=<서버에서만 사용하는 키>
GEMINI_MODEL=gemini-3.1-flash-lite
```

키·모델 미설정, API 오류, 타임아웃, 잘못된 JSON·후보 id·이유는 기본 추천을 반환합니다. SDK 요청은 최대 12초로 제한하고 자동 재시도는 1회 시도만 허용합니다. 클라이언트도 15초 제한을 두며 서버 연결이 끊겨도 브라우저 데이터로 기본 추천을 계산합니다. API 키는 서버 전용 모듈만 읽고 캐시에는 일반 추천 결과만 저장합니다.

### 요청 경합과 비용 제한

동일 날짜·모드의 진행 중 요청은 하나로 합칩니다. 다른 모드의 응답은 해당 모드 캐시만 갱신하며, 도착 시 삭제·완독 상태와 로컬 날짜를 다시 확인합니다. 요청 중 기존 추천을 완독하면 완료 화면을 유지합니다. 미완독 글이 없을 때 클라이언트는 API를 호출하지 않고 서버도 SDK를 호출하지 않습니다.

추천 API 입력은 2 MiB 및 본문 읽기 3초로 제한합니다. 초과나 잘못된 입력은 거절하며 클라이언트는 기본 추천을 사용합니다. Gemini 호출에는 **인스턴스 전체 동시 2회·분당 10회·24시간당 100회**의 메모리 기반 상한을 적용합니다. 한도 소진 시 유료 호출 없이 기본 추천을 반환합니다. 재시작 시 초기화되고 다중 인스턴스 간 공유되지 않으며 사용자별 제한이 아닙니다. 공개 배포 시에는 호스팅의 전역 요청/비용 제한을 함께 설정해야 합니다. 키 없이 사용하는 기본 추천에는 Gemini 비용이 발생하지 않습니다.
